# 有界消费与显式故障恢复

断线时后台自动重连、恢复拓扑声明及订阅；新发布返回不可用，已发送但未确认的发布返回结果未知，由调用方决定重试。相比库内缓存待发送消息，此策略限制内存使用，并使进程故障下的不确定性对调用方可见。

每个订阅配置有限并发和有限预取。停止时先停止接收新消息，再等待在途处理；超过退出期限后取消处理上下文并关闭消费 channel，使未确认消息可重新投递。业务处理器须响应取消，取消上下文本身不能强制终止业务代码。

普通消费重试采用固定延迟档位，通过 TTL 队列和死信路由实现。可靠模式使用持久化 quorum 业务、重试及死信队列，检查必要的可靠转发配置；所有死信转发源启用至少一次转发，不满足要求明确报错。应用主动转发须确认发布成功后再确认原消息，基础设施故障不以耗尽业务重试次数为由丢弃消息。

业务指定的延迟请求使用显式启用、可靠性较弱的延迟 exchange，未启用时普通服务不依赖它。插件不支持 mandatory，延迟消息只有单节点磁盘副本，因此不承诺与普通发布相同的路由反馈和可靠性。此决定接受扩展能力的限制，不将其作为普通可靠重试的基础。

依据：[RabbitMQ DLX](https://www.rabbitmq.com/docs/dlx)、[quorum 死信转发配置](https://www.rabbitmq.com/docs/4.2/quorum-queues)、[延迟插件说明](https://github.com/rabbitmq/rabbitmq-delayed-message-exchange/blob/main/README.md)。
