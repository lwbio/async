# 区分消息身份与订阅身份

每条逻辑消息拥有独立 MessageID，重试保持不变；结果拥有自己的 MessageID，并通过 CorrelationID 指向请求，结果重发保持同一结果 ID。此规则支持业务幂等和结果去重，具体 ID 生成及协议编码方式在设计阶段确定。

事件类型采用完整名称，避免不同 protobuf enum 的相同数字发生冲突。订阅名称无需显式配置：默认从处理器所属包和函数或方法名生成订阅标识并映射到队列，允许调用方覆盖。同一订阅的多个实例共享队列，不同订阅独立消费；同名订阅须保持绑定和消费配置一致。

选择自动命名降低默认配置成本，接受处理器重命名或移动会改变队列身份、旧队列积压不会自动迁移的代价。匿名函数和闭包无法可靠表达业务身份，不同闭包实例可能归为同一订阅；需要区分实例或保持身份时由调用方覆盖名称。
