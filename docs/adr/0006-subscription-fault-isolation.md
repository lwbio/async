# 按订阅隔离明确的消费故障

结果目标不可路由、明确 NACK、消费 channel 关闭及 broker 取消订阅，不再主动关闭共享连接；每个订阅独立停止当前消费代际、保留未确认消息，并按 1 秒起步、最高 30 秒的指数退避重新声明自身拓扑和消费 channel。相比全局重连，这限制局部故障的影响；相比无限原地重试或提前 ACK，它仍允许 broker 恢复未完成消息，并保持有限内存和原有至少一次语义。

发布结果未知仍由 transport 使连接代际失效：在未能安全配对 Return/confirm 的情况下，不能为了隔离保留可疑发布 channel。共享发布通道的确认超时、网络故障仍可能影响全部订阅，不承诺绝对资源隔离。基础设施恢复不增加业务 Attempt；可能重复调用 handler，业务幂等责任不变。

Runtime 的 Ready 表示共享连接和初始订阅建立完成，并不表示所有订阅始终可用；局部恢复通过按订阅的恢复指标观测。停机优先于局部恢复，跨消费及连接代际复用原有并发许可，避免忽略取消的 handler 导致并发失控。
